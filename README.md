# Тёплый круг — кофейня и заказы

Небольшое full-stack приложение: клиентский каталог, корзина и оформление заказа; защищённая панель сотрудника; общий REST API на Express и постоянное хранилище SQLite.

## Запуск

Нужен Node.js 18 или новее и npm.

```sh
npm install
npm start
```

Откройте `http://localhost:3000`. Панель сотрудника: `http://localhost:3000/staff.html`.

### Быстрое офлайн-демо без установки

Чтобы показать внешний вид и действия без Node.js, откройте двойным щелчком `HTML/offline-demo.html`. В офлайн-демо доступны покупательская корзина, кабинет сотрудника, смены, аналитика, журнал администратора и электронный чек с печатью. Вкладки аналитики и журнала считаются по заказам и действиям, сохранённым в этом браузере; они не подключены к SQLite. Для постоянных общих данных SQLite, серверного журнала и генерации PDF запустите основное приложение по инструкции выше.

Для серверной версии начальные учётные записи: администратор `ay3mx` / `ay3mx`; сотрудники `barista1` / `barista1` и `barista2` / `barista2`. Для проверки в школе замените эти начальные пароли перед реальным использованием. База создаётся автоматически в `server/data/coffee.sqlite`.

### Переменные окружения

- `PORT` — порт (по умолчанию `3000`)
- `ADMIN_USERNAME`, `ADMIN_PASSWORD` — логин и пароль администратора при первом создании базы
- `SESSION_SECRET` — секрет подписи сессии
- `NODE_ENV=production` — включает secure-флаг cookie (требуется HTTPS)

## Структура

```text
HTML/                  страницы покупателя и сотрудника
CSS/styles.css         адаптивный дизайн
JS/                    логика каталога, корзины, статусов и панели
Assets/                локальные SVG-иллюстрации товаров
server/server.js       REST API и авторизация сотрудника
server/db.js           схема, seed и запросы SQLite
server/data/           автоматически создаваемая база SQLite
```

## API

- `GET /api/menu` — каталог
- `POST /api/orders` — создать заказ
- `GET /api/orders/:id` — статус заказа и история конкретного клиента
- `POST /api/staff/login`, `POST /api/staff/logout`, `GET /api/staff/session`
- `GET /api/staff/orders`, `PATCH /api/staff/orders/:id/status` — защищённое управление заказами
- `PATCH /api/staff/orders/:id/payment` — отметить способ и статус оплаты
- `GET /api/staff/analytics?from=YYYY-MM-DD&to=YYYY-MM-DD&bucket=day|week|month` — аналитика из SQLite
- `GET /api/staff/analytics.csv`, `GET /api/staff/analytics.pdf` — экспорт отчёта
- `GET /api/admin/activity` — журнал активности, доступный только администратору
- `GET /api/staff/shifts`, `POST /api/staff/shifts/start`, `POST /api/staff/shifts/end` — учёт смен
- `POST /api/customer/orders` и `/api/customer/receipts/:id` — история и чеки по имени и телефону заказа, без клиентской регистрации

Цены и состав позиций рассчитывает сервер по каталогу; присланные браузером суммы не используются. Заказы и строки заказа сохраняются в SQLite одной транзакцией. Чеки сохраняют снимок строк заказа и не меняются вместе с меню. Выручка учитывает только завершённые и оплаченные заказы. Журнал активности append-only: SQLite-триггеры запрещают обновление и удаление его записей через приложение. Сессии панели живут в памяти процесса и завершаются при перезапуске сервера.
